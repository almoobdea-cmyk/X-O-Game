# تدريب «ناطق» العصبي على وسائط مترجمة

خطّ تدريب كامل من «صوت + ترجمة» إلى نموذج يركّب الكلام بصوت أيّ متكلّم. يُشغَّل على سيرفر بمعالج رسومي؛ ما في هذا المجلد هو الشيفرة والاختبار المصغّر الذي يثبت أنّها تعمل من أوّلها إلى آخرها.

## الحلقة التي طلبتها

| الخطوة | ما يحدث | الملف |
|---|---|---|
| 1. يسمع كثيرًا مع الترجمة | `ingest.py` يقرأ ملفّ وسائط + ملفّ ترجمة (SRT/VTT) ويقصّ كلّ سطر ترجمة إلى مقطع صوتي بنصّه | `ingest.py` |
| 2. يجمع الترجمات | يبني `metadata.jsonl`: لكلّ مقطع نصّه ومدّته ومصدره والمتكلّم | `ingest.py` |
| 3. يشكّل الكلمات | مشكّل عصبي خاص (BiLSTM على مستوى الحرف) يُدرَّب على نصوص مشكّلة؛ يُبذَر بمخرجات مهارة التشكيل ثمّ يستغني عنها | `diacritizer.py` |
| 4. يربط الصوت بالحرف | محاذاة قسرية: نموذج CTC صوتي يُدرَّب على المقاطع نفسها ثمّ يُستعمل لتحديد زمن كلّ صوت | `aligner.py` |
| 5. يعيدها ملايين المرات | تدريب نموذج التركيب (FastSpeech مبسّط: مشفّر أصوات + منبّئ مُدد + مفكّك ميل) مع مشفّر مرجعي يلتقط نبرة المتكلّم من أيّ مقطع | `tts_model.py`, `train_tts.py` |
| 6. يرجع ينطقها | نصّ ← تشكيل ← أصوات (محرّك القواعد نفسه) ← ميل ← موجة؛ النبرة من مقطع مرجعي للمتكلّم | `synthesize.py` |
| يعيد الكرة | كلّ دفعة بيانات جديدة تعيد الخطوات 1 إلى 5؛ نقاط الحفظ تُستأنف | `train_tts.py --resume` |

## مصادر البيانات: ما يصلح وما لا يصلح

التدريب على فيديوهات يوتيوب الاعتيادية بتنزيلها جملةً يخالف شروط يوتيوب وحقوق أصحاب المحتوى، ولا أبني أداة لذلك. الخطّ هنا يقرأ أيّ «صوت + ترجمة» تملك الحقّ في استعماله:

1. **SADA** (SDAIA): 668 ساعة سعودية بلهجات نجدية وحجازية وخليجية مع نصوص، رخصة CC BY-NC-SA (غير تجارية؛ للتجاري يلزم اتفاق).
2. **تسجيلاتكم**: برامجكم وبودكاستكم ومذيعوكم مع ترجماتهم؛ هذا أنظف مصدر وأقواه للهجة البيضاء.
3. **فيديوهات يوتيوب برخصة Creative Commons** فقط (مرشّح الرخصة في البحث)، وبإذن صريح لغيرها. مع `yt-dlp` استعمل `--match-filter "license='Creative Commons'"` وحمّل الترجمة المرفوعة من صاحب القناة لا الآلية.
4. **Common Voice العربية** وMGB-2 وQASR للفصحى (تسجيل بحثي).

الترجمة الآلية (التلقائية في يوتيوب) أخطاؤها في اللهجة كثيرة؛ `ingest.py` يستبعد الأسطر التي يرفضها فحص الجودة (مدّة غير منطقية، نسبة أحرف لاتينية عالية، نصّ فارغ).

## التشغيل على السيرفر

```bash
# بيئة
python3 -m venv .venv && source .venv/bin/activate
pip install -r train/requirements.txt        # torch بنسخة CUDA من pytorch.org
apt install ffmpeg nodejs                     # ffmpeg للقصّ، node لمحرّك القواعد

# 1-2 إدخال: manifest.csv فيه أسطر: media_path,subtitle_path,speaker_id,mode(fusha|saudi|auto)
python train/ingest.py --manifest manifest.csv --out data/

# 3 التشكيل: بذر التسميات بمهارة التشكيل (Claude) مرة واحدة، ثمّ تدريب المشكّل الخاص
python train/diacritizer.py train --corpus data/diacritized.txt --out ckpt/diacritizer.pt
python train/diacritizer.py apply --model ckpt/diacritizer.pt --in data/metadata.jsonl --out data/metadata.vocalized.jsonl

# 4 المحاذاة: تدريب CTC على المقاطع ثمّ استخراج مُدد الأصوات
python train/aligner.py train --data data/ --out ckpt/aligner.pt --steps 20000
python train/aligner.py align --model ckpt/aligner.pt --data data/

# 5 التركيب: التدريب الطويل (استأنف بـ --resume)
python train/train_tts.py --data data/ --out ckpt/tts --steps 500000 --batch 32

# 6 النطق بصوت متكلّم من مقطع مرجعي
python train/synthesize.py --model ckpt/tts/latest.pt --ref my_voice.wav --mode saudi --out out.wav "وِشْ رَايِكْ نْرُوحْ السُّوقْ بُكْرَة؟"
```

## الاختبار المصغّر (يعمل على المعالج بلا بيانات حقيقية)

`train/smoke_test.sh` يولّد 240 مقطعًا اصطناعيًا بالمركّب الصيغي مع ملفات SRT، ويمرّرها بالخطوات كلّها بخطوات تدريب قليلة، وينتهي بملفّ صوتي. غرضه إثبات أنّ الأنابيب موصولة، لا جودة الصوت.

## نتيجة الاختبار المصغّر (2026-10-20، معالج فقط، 60 مقطعًا اصطناعيًا، 80 خطوة لكلّ مرحلة)

| المرحلة | النتيجة |
|---|---|
| الإدخال من SRT | 60 من 60 مقطعًا قُبلت، 0 مرفوضة |
| المشكّل الحرفي | 88 جملة تدريب / 4 تحقق؛ دقّة الحرف على التحقق 0.75 بعد 80 خطوة (0.98 على جمل التدريب نفسها، أي حفظ لا تعميم؛ الجولة الحقيقية تحتاج آلاف الجمل) |
| محاذاة CTC | خسارة 18.4 → 3.0 في 50 خطوة؛ المُدد المستخرجة بعد 80 خطوة غير ناضجة (تتكدّس على صوتين) وهذا متوقّع قبل آلاف الخطوات |
| نموذج التركيب | 24.4 مليون معامل؛ 80 خطوة؛ الخسارة تتناقص |
| النطق | أخرج ملفًا صوتيًا من نصّ سعودي بمقطع مرجعي؛ المُدد المتنبَّأ بها 1 إطار لكلّ صوت لأنّ المنبّئ لم يتدرّب بعد |

الخلاصة: الأنابيب موصولة من الصوت المترجم إلى النطق بلا نموذج خارجي، وجودة الصوت تأتي من التدريب الطويل على بيانات حقيقية لا من هذا الاختبار.

## الحجم والزمن المتوقّع على معالج رسومي واحد (A100/H100)

| الهدف | بيانات | خطوات | زمن تقريبي |
|---|---|---|---|
| صوت مفهوم بلهجة واحدة | 20 ساعة | 200 ألف | يوم |
| متعدّد المتكلّمين مع نقل نبرة | 100 ساعة | 500 ألف | 3 إلى 4 أيام |
| جودة إنتاج | 300+ ساعة + مفكّك موجة عصبي (HiFi-GAN) | مليون+ | أسبوع+ |

المفكّك الحالي Griffin-Lim (بلا تدريب، صوت معدني قليلًا)؛ الترقية إلى HiFi-GAN مدرَّب على البيانات نفسها هي ما يرفع الجودة إلى مستوى الإنتاج، وشيفرته خطوة لاحقة.
